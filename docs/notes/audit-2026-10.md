# Audit, 2026-10-02: ml-stack as an embedded dependency

Read from the position of a program that embeds `ml_stack.serve` and `ml_stack.client`
(and possibly the fleet) as an optional dependency. Baseline: commit cf364a1, Python 3.13.5,
macOS. Evidence is file:line at that commit.

## Checked and clean

- Importing `ml_stack`, `.serve`, `.client`, `.fleet`: no stdout or stderr, no socket
  connection, no file written, no heavy module loaded (psutil, numpy, torch stay unloaded).
- `ML_STACK_HOME` and `ML_STACK_CACHE` (`home.py:20-60`) move all state and cache; documented
  in `docs/install.md`.
- A full lease and stop through `ServerManager` against a fake llama-server wrote only
  under the state directory (a pruned per-port log, `servers.json`, `servers.lock`).
- Fleet file routes: `safe_relpath` (`fleet/files.py:59`) refuses absolute paths, `..` and
  escapes after `resolve()`. Bearer tokens are compared with `compare_digest`, the passphrase
  is stretched with scrypt (`fleet/discovery.py:101`), discovery packets are HMAC-signed.
  Archive extraction checks names first.
- Gates: `scripts/budgets` clean at baseline (1535 of 1535).

## Fixed on this branch

See `git log main..agent/audit`: inference-proxy host injection, ServerManager `close()` and
context manager, pid reuse before killing a recorded server, Windows `port_is_free`, stale
client family cache after a server restart, tar extraction fallback, the embedding section in
`docs/serving.md`.

## Backlog, most important first

1. **Without psutil, process control silently does nothing.** `serve/process.py:126`
   (`pid_exists` returns False on `ImportError`), then `kill_process_tree` (`:157`) and
   `kill_pid` return before acting, and `merge_state` (`serve/leases.py:25`) drops every
   record. Measured: with psutil unimportable, `kill_process_tree` on a live child returns
   `[]` and the child keeps running, so `serve()` leaks the llama-server on exit. psutil
   sits in the `serve` extra only (`pyproject.toml:48`), and `ml-stack` alone installs
   fine and imports fine. Approach: make psutil a core dependency (it is 25 MB of nothing
   and `tests/test_packages_install_anywhere.py:41` pins the dependency list, so that test
   changes with it), or raise a clear error from `pid_exists` when it is missing. Needs a
   decision because `docs/packages.md` promises a stdlib-only core.
2. **A killed embedder leaks its llama-server.** `process_group_kwargs`
   (`platform.py:77`) starts servers in their own session, and nothing registers `atexit`,
   a signal handler or `PR_SET_PDEATHSIG`. SIGTERM or SIGKILL of the host leaves a model
   resident in GPU memory until the next lease on that port. Approach: an opt-in
   `ServerManager(stop_on_exit=True)` that registers `atexit` and SIGTERM handlers calling
   `close()`; on Linux add a parent-death signal through `preexec_fn`.
3. **No `ml_stack/__init__.py`.** `src/ml_stack` is a namespace package, so there is no
   `ml_stack.__version__`, no `NullHandler` on the `ml_stack` logger, and no single place to
   state the public surface. Only 9 modules use `logging`; the rest write through
   `log.say`, which prints to stdout by default (`log.py:3-6`), and `lock.only_one`
   defaults `announce=print` (`lock.py:116`). An embedder must call `log.to(...)` to catch
   them. Approach: add `__init__.py` with `__version__` and a `NullHandler`; make
   `say` log at INFO when no listener is set and the call is not from a CLI. (Overlaps the
   packaging/public-API branch.)
4. **Fleet daemon speaks plaintext HTTP on 0.0.0.0.** `fleet/daemon.py:396` binds all
   interfaces by default and the bearer token travels unencrypted, so anyone on the LAN who
   can sniff traffic gets the token, and with it `/serve`, `/files` PUT and `/infer`. The
   token is derived from the passphrase (`discovery.py:246`), so it never rotates. Approach:
   document the threat model in `docs/fleet.md`; add `--host 127.0.0.1` guidance for an
   embedder that only borrows a peer; consider per-request HMAC with a nonce instead of a
   static bearer.
5. **Unvalidated request framing in the daemon.** `fleet/api.py:187,383,542` call
   `int(Content-Length)` bare. A non-numeric value raises inside the handler (stderr
   traceback from `socketserver`), and a negative one makes `rfile.read(-1)` wait for EOF
   while holding a thread. The PUT route also parses `Content-Range` with bare `int()`
   (`api.py:546`). Approach: one `_content_length()` helper returning 400 on a bad value
   and 413 above a cap.
6. **Per-port log files are pruned per port only.** `serve/backend.py:42-48` keeps
   `LOGS_KEPT` logs for each (name, port) pair, and `serve()` picks a random free port each
   time, so an embedder that serves repeatedly accumulates one log per start in
   `$ML_STACK_HOME/logs`. Approach: prune by age or total count across ports.
7. **`_DEFAULT = ServerManager()` is built at import** (`serve/manager.py` end of file),
   so the module-level `serve()` shares one manager across threads and callers; two embedders
   in one process share state. Approach: build it on first use, and document that
   `serve(manager=...)` is the isolated form.
8. **Swallowed exceptions.** 172 `except Exception` sites are budgeted; the ones that
   matter to an embedder are `serve/backend.py:240,828`, `serve/escalation.py:172,204`,
   `serve/preflight.py:144,183`, `client/chat.py:233`. Each turns a failure into a
   default. Approach: narrow to the exceptions the call raises, or log at debug with the
   exception.
9. **Test blind spots.** 107 of 345 modules are named by no test file
   (`scripts/mutate --unmeasured`), and `mutation-survivors` is 0 only because the last
   campaign sampled 2 of 3708 functions (2026-09-18). `serve/process.py` and
   `serve/ports.py` race paths (server dies between `is_healthy` and `adopt`, port taken
   between `port_is_free` and `Popen`) have no test.
10. **Python pin.** `requires-python = ">=3.13,<3.14"` (`pyproject.toml:10`) makes
    `pip install` fail outright on 3.14 and below 3.13; handled on the packaging branch.

Pid reuse beyond what is fixed: `merge_state` and `already_up` still use `pid_exists` alone,
so a stale record can keep a dead server looking alive until its pid is free. The fix is the
same `same_process` check; left because it changes what `status` prints.
